## 1. 设计目标（对应需求）

| 需求 | 落地方式 |
|------|----------|
| ① DNF 手游式 2D 横版 demo | 单房间 + 1 角色 + 固定刷怪 + 清怪过关 |
| ② 完整 GAS | §4.8：`gas/` 六模块 + ASC + GameplayCue |
| ③ 代码独立 | 不 import 卡牌/塔防代码；可参考其分层思路 |
| ④ 商用流程 | 配置表 + core/view 分离 + 输入回放校验（见 §4.0 商用对照） |
| ⑤ 本地单机 + 确定性回放 | 固定 tick + seed + 输入序列 → 完全一致的事件流 |
| ⑥ 操作 | 8 向摇杆 + 跳跃 + 普攻连击 + 3 技能（CD+MP，地面限定） |
| ⑦ 表现 | Spine 动画；View 只消费逻辑事件，不算战斗 |

## 2. Demo 范围（MVP 边界）

**做：**
- 一个场景、一个可玩角色、3 个主动技能 + 普攻连击
- 单屏房间，敌人固定摆放，清完所有怪胜利
- 玩家死亡失败
- 血条 / 蓝条 / 技能 CD / Buff 图标 / 伤害数字 / 暂停
- Buff/Debuff 第一版即支持

**不做：**
- 多关卡、选关、存档
- 养成（等级、装备、技能升级）
- 联网联机（架构预留校验能力，demo 不实现网络层）

## 3. 分层架构

```
配置(data/*.ts → 后期 JSON 表)
        ↓
battle-core(纯 TS，零 cc) — 固定 tick 推进 + GAS + Hitbox 判定
        ↓
BattleEvent[] / BattleFrame[]（每 tick 事件快照）
        ↓
battle-view(cc + Spine) — 读事件驱动动画/UI，不做任何战斗计算
        ↘ 服务器日后用同一份 battle-core + 输入序列重跑校验 ↙
```

- **逻辑层 `scripts/battle-core/`**：纯 TypeScript，**禁止 import 'cc'**，可在 Node / 服务器运行。
- **表现层 `scripts/battle-view/`**：依赖 `cc` + Spine，读取战斗事件逐 tick 更新节点/动画/UI。
- **数据 `scripts/data/`**：角色、技能、Buff、关卡、Hitbox 等配置；demo 用 TS 常量，生产换 JSON 表。

> 与卡牌/塔防的关系：**只借鉴**「core/view 分离、tick 驱动、指令队列、seed 随机、事件总线」等流程；**不 import** 其任何模块。

### 3.1 架构设计原则（标准约束）

以下原则是**强制性**的，写代码与扩展时必须遵守；违反会导致无法回放校验或逻辑/表现耦合。

| # | 原则 | 含义 | 违反后果 |
|---|------|------|----------|
| P1 | **逻辑与表现分离** | `battle-core` 零 `cc` 依赖；View 只读 `BattleEvent` | 无法在 Node/服务器跑校验 |
| P2 | **固定 Tick 驱动** | 逻辑时间 = `tick × Δt`；禁止用 `Date.now()` / 帧 `dt` 做战斗判定 | 同输入不同结果，回放失败 |
| P3 | **输入即事实** | 一切玩家行为先变成 `InputCommand(tick, type, payload)` 再进逻辑 | 无法录制与重放 |
| P4 | **GAS 唯一修改口** | HP/MP/Tag/Buff/CD 只通过 ASC 的 GA/GE 修改；System 不直接改数值 | 状态散落，Buff 失效 |
| P5 | **事件单向流出** | 逻辑层 `emit` 事件；View 订阅消费，**不回写**逻辑 | 表现影响战斗结果 |
| P6 | **Resolver 无状态** | 伤害/暴击公式在纯函数里；不持有 `world` 引用 | 难以测试与复用 |
| P7 | **配置只读** | 运行时只读 `GameConfig`；不改表内数据 | Determinism 被破坏 |
| P8 | **System 单一职责** | 每个 System 只处理一个阶段；跨阶段用 World/Context 传数据 | 管线顺序混乱 |

**标准三层职责边界：**

```
┌─────────────────────────────────────────────────────────┐
│  battle-view     │  输入采集、Spine/UI、相机、音效        │  不算战斗
├─────────────────────────────────────────────────────────┤
│  battle-core     │  Tick、GAS、碰撞、AI、胜负、事件产出   │  不算画面
├─────────────────────────────────────────────────────────┤
│  data            │  配置表、注册表                        │  不参与 runtime 逻辑
└─────────────────────────────────────────────────────────┘
```

### 3.2 标准术语表（GAS + 本项目）

对齐 UE GAS 官方命名，读文档/源码时统一用语：

| 术语 | 英文 | 含义 |
|------|------|------|
| **ASC** | AbilitySystemComponent | 实体上管理技能/Buff/属性/Tag 的**唯一组件** |
| **GA** | GameplayAbility | 一次「技能/普攻」的逻辑实例（激活、Task 链、结束） |
| **GE** | GameplayEffect | 改属性、挂 Tag、周期效果的 Buff/Debuff |
| **AttributeSet** | — | HP、MP、ATK 等属性集合；GE 通过 Modifier 修正 |
| **Tag** | GameplayTag | 层次化状态标签，如 `State.Airborne`、`State.Stunned` |
| **AbilityTask** | — | GA 内的多 tick 子步骤（等帧、开 Hitbox、施加 GE） |
| **GameplayCue** | — | 纯表现指令（特效/音效）；逻辑只 emit，View 执行 |
| **Spec** | AbilitySpec / GameplayEffectSpec | **配置**中的静态定义（CD、Cost、Tasks） |
| **ActiveGE** | ActiveGameplayEffect | GE 施加后在 ASC 内的**运行时实例** |
| **Tick** | — | 逻辑帧序号 `0,1,2…`；20 tick/s ⇒ 每 tick = 50ms |
| **InputCommand** | — | 某一 tick 的玩家/AI 输入记录 |
| **BattleEvent** | — | 逻辑层产出的事实（伤害、移动、技能开始…） |
| **Owner / Avatar** | — | UE 概念：Owner 持久持有者，Avatar 场景化身；demo 中合一 |

### 3.3 运行时模型（架构如何运转）

#### 3.3.1 战斗生命周期

```
[未开始] ──startBattle()──► [进行中] ──BATTLE_END──► [已结束]
                              │  ▲
                              │  │ pause/resume（冻结 tick）
                              └──┘
                         每 tick: step() 推进
```

| 阶段 | 触发 | 产出 |
|------|------|------|
| **装配** | `createBattle(config, setup)` | `BattleWorld` + Systems + 实体，**尚未 step** |
| **开始** | 首次 `step()` 或显式 `onBattleStart` | `BATTLE_START` 事件 + 初始 snapshot |
| **进行中** | 每 tick `step()` | 本 tick 的 `BattleEvent[]` |
| **结束** | `BattleResultSystem` 判定 | `BATTLE_END` + `world.finish()` |

#### 3.3.2 双驱动模式（同一套 Core）

```
模式 A — Headless（校验 / 离线回放）          模式 B — 实时（Demo 入口）
────────────────────────────────────          ────────────────────────────
runBattle(config, setup, inputLog)            BattleEntry.update(dt)
  └─ 预先给定全部 InputCommand                  ├─ 采集输入 → enqueueInput
  └─ while: step()                              ├─ BattleRunner.update(dt)
  └─ 一次返回全部 Event[]                       │    └─ 累加 dt → 多次 step()
                                                └─ View 消费每 tick 的 Event[]
```

两种模式**必须**走同一个 `BattleCore.step()` → `BattleDirector.update()`，保证结果一致。

#### 3.3.3 单 Tick 数据流（核心循环）

```
InputCommand(tick=N) 入队
        │
        ▼
BattleCore.step()
        │
        ▼
BattleDirector ──按序──► System[0..9].update(world, context)
        │                      │
        │                      ├─ 读：world.entityManager / asc / hitboxManager
        │                      ├─ 写：实体状态、ASC、Hitbox 池
        │                      └─ emit：BattleEvent → eventBus
        ▼
world.tick++
eventBus.drain() ──► BattleEvent[] 返回给 Application / View
```

#### 3.3.4 逻辑 ↔ 表现 边界（每 tick）

```
View                          Core                         View
────                          ────                         ────
摇杆/按键 ──InputCommand──►  step() 算完
                               │
                               └──BattleEvent[]──► EntityView 移位置
                                                 ├► Spine 切动画
                                                 ├► HUD 更血条/CD
                                                 └► 飘字 / Buff 图标
```

View **不得**：自己扣血、自己判 CD、自己检测 Hitbox。

#### 3.3.5 GAS 在 Tick 中的位置

```
InputSystem 收到 Skill1
      │
      ▼
AbilitySystem 调用 ASC.tryActivateAbility()
      │
      ├─ 检查 Tag / MP / CD          ← GE 提供的 Tag、AttributeSet 的 MP
      ├─ Activate → 启动 AbilityTask 链
      │     ├─ WaitTicks
      │     ├─ SpawnHitbox ──────────► CollisionSystem 本 tick/后续 tick 检测
      │     ├─ ApplyGameplayEffect ──► TagTickSystem 后续 tick 维护
      │     └─ PlayAnimEvent ────────► GameplayCue 事件 → View
      └─ End → 进入 CD
```

### 4.1 目录总览

```
scripts/
  data/                          ← 配置表（config-types + sample-data）
  battle-core/
    index.ts                     ← 对外 API：createBattle / runBattle / types
    application/                 ← 用例层（实时驱动 / 回放入口）
    core/                        ← 内核：World、Core、Director、Runner
    command/                     ← 输入指令与 tick 对齐队列
    system/                      ← 固定 tick 系统管线（每系统一职责）
    entity/                      ← 战斗实体 + IAbilitySystemInterface
    manager/                     ← 实体/Hitbox 等对象管理器
    gas/                         ← 完整 GAS（对齐 UE 模块划分）
    combat/                      ← 伤害/受击/连击（调用 GAS Attribute & GE）
    collision/                   ← AABB、Hitbox/Hurtbox、逐 tick 检测
    movement/                    ← 移动、重力、跳跃、地面检测
    ai/                          ← 敌人行为（状态机）
    resolver/                    ← 纯函数结算器（伤害、目标）
    event/                       ← 事件类型 + EventBus
    record/                      ← 帧记录、输入日志、回放
    replay/                      ← 确定性 hash / 校验辅助
    flow/                        ← 工厂装配、胜负判定
  battle-view/                   ← 表现层（见 §7）
```

### 4.2 分层职责（商用分层）

| 层 | 目录 | 职责 | 商用参考 |
|----|------|------|----------|
| **Application** | `application/` | 对外用例：开局、收输入、固定 tick 驱动、暂停 | Lyra `GameMode`；手游 BattleSceneController |
| **Core** | `core/` | 战斗生命周期；World 上下文；Director 调度 | VALORANT 服务器 Tick 循环；帧同步 BattleCore |
| **System** | `system/` | 每 tick 分阶段执行，**禁止**跨阶段耦合 | UE Mass/Ecs；Riot 固定阶段处理 |
| **Command** | `command/` | 输入序列化、按 tick 出队，保证可回放 | 王者帧同步 InputFrame；DNF tick 冷却 |
| **Entity + GAS** | `entity/` + `gas/` | 实体挂载 ASC；技能/Buff/属性全走 GAS | Fortnite ASC；Lyra HeroComponent |
| **Manager** | `manager/` | 实体池、Hitbox 池集中 CRUD | 手游 UnitManager / EntityManager |
| **Resolver** | `resolver/` | 无状态伤害/暴击结算 | 各项目 DamageFormula 纯函数层 |
| **Event + Record** | `event/` + `record/` + `replay/` | 逻辑产出事实；日志与 hash 校验 | 帧同步录像；DNF 战斗日志审计 |

**依赖规则（自下而上，上层只能调下层）：**
```
application → core → system → (entity | gas | movement | collision | ai | combat | resolver)
                ↓
              event → record
data/config ──→ flow（装配时注入，runtime 只读）
```

### 4.3 Core 层

| 文件 | 职责 |
|------|------|
| `core/battle-core.ts` | 门面：`enqueueInput()` / `step()` / `runUntilFinished()`；持有 `BattleWorld` |

| `core/fixed-tick.ts` | `TICK_RATE = 20`、tick ↔ 毫秒换算 |

### 4.4 Application 层

| 文件 | 职责 |
|------|------|
| `application/battle-application.ts` | 用例入口：`startBattle(config, params)`、`update(dt)`、`enqueueInput(cmd)`、`pause/resume` |
| `application/battle-session.ts` | 单场会话：inputLog 累积、result 快照，供上报/回放 |

### 4.5 Command 层（确定性输入）

| 文件 | 职责 |
|------|------|
| `command/input-command.ts` | 指令枚举：Move、Jump、NormalAttack、Skill1/2/3、Pause；带 `tick` 时间戳 |
| `command/input-command-queue.ts` | 入队/按 tick 出队；同 tick 多条按入队序 |
| `command/input-buffer.ts` | 预输入缓冲（跳跃/普攻/技能可缓存 ≤ N tick） |

### 4.6 System 管线（每 tick 执行顺序）

参考 **VALORANT 服务器 Tick** 与 **DNF 类动作帧** 的通用顺序：**先收输入 → 再推进技能/状态 → 再移动 → 再碰撞结算 → 最后判胜负**。顺序写死在 `BattleDirector`，System 间通过 `BattleWorld` 通信，不互相直接调用。

| 顺序 | System | 职责 |
|------|--------|------|
| 1 | `InputSystem` | 出队本 tick 指令 → 写入 `BattleSystemContext` |

## 5. 核心机制

### 5.1 确定性（服务器校验前提）

对齐 **DNF/帧同步手游** 的商用校验模型：战斗 = **`初始配置 + seed + 输入指令序列（带 tick 时间戳）`** 的纯函数。

- 逻辑层以固定 tick 推进，**不依赖 `dt` 浮点累积**。
- 所有随机（暴击、AI 分支等）走 `SeededRandom`。
- 相同输入 ⇒ 完全相同的事件序列与最终胜负。
- 客户端上报 `seed + inputs + result`；服务器用同一份 `battle-core` 重跑比对。

**两种驱动方式（与卡牌项目一致）：**

```
A. 一次性跑完（校验/离线回放）：
   runBattle(config, setup, inputLog) → 全部 BattleEvent[]

B. 实时交互（demo 入口）：
   每帧 collectInput → enqueueInput(tick, cmd) → step() → View 消费本 tick 事件
```

### 5.2 输入与操作

| 控件 | 逻辑行为 |
|------|----------|
| 左下虚拟摇杆 | 8 方向归一化移动向量；无输入则减速停下 |
| 跳跃键 | 地面可跳；空中不可二段跳（demo 默认） |
| 普攻键 | 连点进入连招段（配置驱动段数与 Hitbox）；**地面/空中均可** ✓ |
| 技能 1/2/3 | 消耗 MP + 进入 CD；**仅地面可释放**（Tag 不含 `State.Airborne`）；**朝面向方向**释放 ✓ |
| 暂停 | 停止向 core 送新输入；逻辑 tick 暂停（见 §5.6） |

**技能瞄准（已确认）**：不选方向、不选目标。Hitbox 沿实体当前 `facing`（左/右）及相对偏移生成；demo 不做全屏索敌、不做点击选点。

技能释放检查顺序（GAS 标准）：
```
Tag 限制 → 资源/MP → CD → 自定义 CanActivate → Activate → 执行 AbilityTask 链
```

### 5.3 受击与状态（格斗/DNF 通用规则，demo 默认值）

| 状态 | 规则 |
|------|------|
| **硬直（Hitstun）** | 受击后挂 `State.Stunned` 若干 tick，不可移动/攻击；普攻/技能被打断 |
| **浮空（KnockUp）** | 受击力达阈值 → 挂 `State.Airborne` + 向上速度；落地前不可释放技能 |
| **击飞（KnockBack）** | 附加水平速度；撞墙速度归零 |
| **无敌帧（I-Frames）** | 倒地起身或受击后挂 `State.Invincible` 短 tick；Hurtbox 不接收伤害 |
| **霸体（Super Armor）** | 技能期间挂 `State.SuperArmor`；**受击扣血但不打断、不硬直** |
| **连击数** | 对敌人连续造成命中的 tick 间隔 ≤ 90 tick（约 4.5s）则 +1；超时或未命中清零；View 显示 |

Hitbox 判定：
- 全部用**轴对齐矩形（AABB）**，在逻辑层每 tick 检测。
- 每个 AbilityTask 可在指定 tick 激活/关闭 Hitbox。
- Hurtbox 挂在实体上；`State.Invincible` 时跳过伤害。

### 5.4 GAS 运行机制

模块文件划分见 **§4.8**；此处只描述运行时行为。

**GameplayAbility（GA）**
- 由 `GameplayAbilitySpec`（配置）+ `AbilitySpec`（授予实例）驱动。
- 激活链：`RequiredTags` / `BlockedTags` → MP 消耗 → CD → `CanActivate()` → `Activate()` → 执行 `AbilityTask` 序列 → `End()`。

**GameplayEffect（GE）**
- `Instant`：立即 Modifier 改 Attribute 或触发一次性逻辑。
- `Duration`：持续 N tick，由 `TagTickSystem` 倒计时并移除。
- `Infinite`：永久直到驱散。
- 支持：`modifiers[]`、`grantedTags[]`、`immunityTags[]`、`periodicEffect`（周期 GE）。

**AbilityTask（多 tick 技能片段）**
- `WaitTicks` / `ApplyGameplayEffect` / `SpawnHitbox` / `ApplyImpulse` / `PlayAnimEvent`（写 Cue 事件，View 播 Spine）。

**GameplayCue**
- 逻辑层只 emit `GameplayCue` 事件（含 cueTag、位置）；特效/音效/震屏在 View 查 `cue-config` 播放。

> 配置驱动：新技能 = `gas-registry` 加 `AbilitySpec` + 组合 Task + 引用 GE；仅全新机制才新增 Task 类型。

### 5.5 伤害管线

```
基础伤害(ATK×倍率+固定值)
  → 暴击判定(SeededRandom)
  → 攻方增伤 GE
  → 防方减伤 GE
  → 护盾吸收
  → 扣 HP
  → 死亡判定
  → 写入 Combo / 受击反应事件
```

### 5.6 MP 与 CD

- **MP**：释放技能时扣除；**自然回复** demo 默认 5 MP/s（每 tick 按固定增量回）。
- **CD**：以 tick 为单位倒计时；ASC 统一管理。
- View 层读事件更新蓝条与 CD 遮罩，**不自行计时**。

### 5.7 关卡与 AI

- **单屏房间**：配置 `roomBounds`（AABB），实体不可越界。
- **相机**：View 层锁定玩家 X（可选 Y 微跟随），逻辑层不关心相机。
- **刷怪**：`StageConfig.enemies[]` 固定 `{ configId, x, y }`，开局一次性生成。
- **AI**：简单状态机——待机 → 发现玩家（距离阈值）→ 追击 → 进入攻击范围放普攻 Ability。

### 5.8 胜负

- **胜利**：房间内所有敌人 `HP ≤ 0`。
- **失败**：玩家 `HP ≤ 0`。
- 结束时发 `BATTLE_END` 事件，带 `{ result: 'win' | 'lose' }`。

## 6. 战斗事件（供 View 回放）

## 9. 如何扩展

- **加技能**：在 `abilities` 加 `AbilitySpec`，组合已有 Task + GE。
- **加 Buff**：在 `gameplayEffects` 加 `GameplayEffectSpec`。
- **加新机制**：新 `AbilityTask` 或 `EffectModifier` 类型 → 注册 → 配置引用。
- **加角色/敌人**：`HeroConfig` / `EnemyConfig` + Spine 资源，不改主流程。
- **加表现**：`view-config.ts` 映射 `abilityId → 特效/音效`，View 查表播放。
