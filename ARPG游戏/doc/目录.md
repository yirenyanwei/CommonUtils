# ARPG 游戏 · 目录与文件职责

> 路径均相对 `assets/ARPG游戏/scripts/`。  
> 阅读建议：先看**分层总览**，再按兴趣查阅对应目录。

---

## 分层总览

```
scripts/
 ├─ data/              【数据层】 配置定义 & 静态数据，运行时只读
 ├─ battle-core/       【逻辑层】 纯 TypeScript，零 cc 依赖，可在 Node 环境运行
 │    ├─ core/         固定 tick 基础设施
 │    ├─ event/        事件类型 & 总线
 │    ├─ command/      输入指令 & 队列
 │    ├─ entity/       战斗实体
 │    ├─ gas/          Gameplay Ability System（GAS 核心）
 │    ├─ manager/      实体 & Hitbox 生命周期管理
 │    ├─ collision/    AABB 碰撞工具
 │    ├─ movement/     重力 & 物理积分
 │    ├─ resolver/     伤害公式（纯函数）
 │    ├─ combat/       伤害结算编排
 │    ├─ ai/           敌人 AI 决策
 │    ├─ system/       System 管线（10 个，每 tick 按序执行）
 │    ├─ record/       战斗录像
 │    ├─ replay/       离线回放
 │    ├─ flow/         装配 & 胜负
 │    └─ application/  逻辑层对外门面
 └─ battle-view/       【表现层】 Cocos Creator 组件，只消费事件 & 发送指令
```

**核心约束：**
- `battle-core/` 内任何文件不得 `import { ... } from 'cc'`
- `battle-view/` 不得调用 `asc.*`、`entity.*` 写方法，只发 `InputCommand`
- 所有随机通过 `SeededRandom`，所有时间通过 `tick`（整数）

## data/ — 数据层

> 单一事实来源。运行时只读，所有游戏数值配置都在这里。

| 文件 | 职责 |
|---|---|
| `config-types.ts` | **全部配置结构定义**（接口 & 枚举）。`GameplayAbilitySpec`、`GameplayEffectSpec`、`CharacterConfig`、`StageConfig`、`GameConfig` 等所有数据结构的 TypeScript 类型。Tags 命名空间（所有 GameplayTag 字符串常量）。 |
| `gas-registry.ts` | **GAS 注册表**。所有 `GameplayAbilitySpec`（GA）和 `GameplayEffectSpec`（GE）的静态数据——普攻三段、三个技能、各种 Buff/Debuff——以及 `gasRegistry` 单例，提供 `getAbilitySpec(id)` / `getEffectSpec(id)` 查询。 |
| `sample-data.ts` | **Demo 示例数据**。`GAME_CONFIG`（全局物理/暴击参数）、`HERO_CONFIG`（骑士）、`ENEMY_GOBLIN`、`ENEMY_ORC`、`STAGE_1`（关卡布局），以及 `getCharacterConfig(id)` / `getStageConfig(id)` 查询函数。 |

## battle-core/core/ — 固定 Tick 基础设施

> 战斗运行的时间引擎和最顶层编排，是整个逻辑层的骨架。

| 文件 | 职责 |
|---|---|
| `fixed-tick.ts` | **时间常量**。`TICK_RATE=20`、`FIXED_DT=0.05s`、`tickToSeconds`/`secondsToTick` 工具函数。逻辑层禁止用 `Date.now()`，全部走 `tick`。 |
| `seeded-random.ts` | **确定性随机**（mulberry32 算法）。`SeededRandom` 类，提供 `next()`/`nextInt()`/`chance(p)` 方法。同 seed 同顺序 → 完全相同的随机序列，是回放和服务器校验的基础。 |
| `battle-world.ts` | **世界上下文中心**（BattleWorld）。持有 `GameConfig`、`StageConfig`、`SeededRandom`、`BattleEventBus`，以及 `EntityManager`、`HitboxManager`、`DamageResolver`（由工厂注入）。System 通过 `world` 访问一切跨 tick 状态，不直接互相持有引用。`finish(result)` 方法结束战斗并 emit `BATTLE_END`。 |
| `battle-director.ts` | **System 管线调度器**（BattleDirector）。持有有序的 `BattleSystem[]`，每 tick 按序调用。定义 `BattleSystem` 接口和 `BattleSystemContext`（本 tick 的意图传递对象：`moveX/Y`、`jumpRequested`、`skillSlot`、`hitResults`）。战斗结束则立即截断后续 System。 |
| `battle-core.ts` | **战斗逻辑门面**（BattleCore）。对外提供三个方法：`enqueueInput(cmd)` 存入指令；`step()` 推进一个 tick 并返回本 tick 全部 `BattleEvent[]`；`runUntilFinished()` 用于 Headless 模式一次性跑完。 |
| `battle-runner.ts` | **实时 Tick 累加器**（BattleRunner）。`update(deltaTime)` 将渲染帧的 `dt` 累加，每满 `FIXED_DT` 调用一次 `core.step()`，解耦渲染帧率与逻辑 tick 速率。`paused` 字段控制暂停。 |

## battle-core/event/ — 事件总线

> 逻辑层输出侧。产出事件是逻辑→表现的唯一通道。

| 文件 | 职责 |
|---|---|
| `battle-event.ts` | **所有事件类型**。`BattleEventType` 枚举（14 种）和每种事件的 payload 接口，以及联合类型 `BattleEvent`。包含：`BATTLE_START/END`、`ENTITY_MOVE/DEATH`、`ABILITY_ACTIVATE/END`、`DAMAGE/HEAL`、`ATTRIBUTE_CHANGE`、`GE_APPLIED/REMOVED`、`TAG_CHANGED`、`COMBO_CHANGED`、`GAMEPLAY_CUE`。 |
| `battle-event-bus.ts` | **事件缓冲区**（BattleEventBus）。`emit(event)` 写入；`drain()` 取出并清空全部事件。每 tick 末尾由 `BattleCore.step()` 调用 `drain()` 交给表现层。 |

---

## battle-core/command/ — 输入指令

> 逻辑层输入侧。玩家操作的序列化表示，是确定性回放的关键。

| 文件 | 职责 |
|---|---|
| `input-command.ts` | **指令类型定义**。`MoveCommand`（dx/dy）、`JumpCommand`、`NormalAttackCommand`、`SkillCommand`（Skill1/2/3）、`PauseCommand` 及联合类型 `InputCommand`。每条指令携带 `tick` 时间戳。 |
| `input-command-queue.ts` | **预输入队列**（InputCommandQueue）。按 `tick` 分桶存储，`enqueue(cmd)` 入队，`dequeueForTick(currentTick)` 取出所有 `tick ≤ currentTick` 的指令（支持追帧）。 |

## battle-core/entity/ — 战斗实体

| 文件 | 职责 |
|---|---|
| `character-entity.ts` | **CharacterEntity**——玩家和怪物的运行时数据对象。持有：位置/速度/面向/存活状态；`AbilitySystemComponent`（asc）；普攻连招状态（`comboIndex`、`comboCancelTicks`、`comboResetTimer`）。构造时自动根据配置向 asc 授予技能。 |

## battle-core/gas/ — Gameplay Ability System

> 本项目最核心的模块。对应 UE GAS 的 TypeScript 实现。

### 核心入口

| 文件 | 职责 |
|---|---|
| `ability-system-component.ts` | **ASC（AbilitySystemComponent）**——GAS 的唯一管理入口。持有 `AttributeSet`、`GameplayTagContainer`、`ActiveGameplayEffect[]`（运行中 GE）、`Map<id, AbilitySpec>`（已授予技能）、当前 `ActiveAbility`（执行中的技能 Task 链）。核心 API：`grantAbility`、`tryActivateAbility`（9 步激活流程）、`advanceActiveAbility`（Task 链推进）、`applyGameplayEffect`、`tickActiveEffects`。 |

### gas/attribute/

| 文件 | 职责 |
|---|---|
| `attribute-set.ts` | **AttributeSet**（对应 UE `UAttributeSet`）。持有 hp/maxHp/mp/maxMp/atk/def/moveSpeed 七个属性，每个属性有 `base`（基础值）和 `current`（当前值）两层。`modifyCurrent(name, delta)` 带 clamp；`get(name)` 动态查找。 |

### gas/tag/

| 文件 | 职责 |
|---|---|
| `gameplay-tag-container.ts` | **GameplayTagContainer**（对应 UE `FGameplayTagContainer`）。用 `Set<string>` 存储当前实体持有的 Tag 列表。`hasAll(tags)` / `hasAny(tags)` 供 GA 检查条件使用。 |

### gas/effect/

| 文件 | 职责 |
|---|---|
| `active-gameplay-effect.ts` | **ActiveGameplayEffect**（对应 UE `FActiveGameplayEffect`）。GE 被施加后的运行时实例。持有唯一 `handle`、原始 `spec`、`remainingTicks`（Duration 类型倒计时）、`periodicTimer`（周期触发计时器）。 |

### gas/ability/

| 文件 | 职责 |
|---|---|
| `ability-spec.ts` | **AbilitySpec**（对应 UE `FGameplayAbilitySpec`）。已授予技能的运行时实例，持有 `remainingCooldownTicks`（CD 状态）。`tickCooldown()` 每 tick -1；`isOnCooldown` 查询。 |

### gas/task/

> Task 链是 GA 在多个 tick 内按序执行子步骤的机制（对应 UE `UAbilityTask`）。

| 文件 | 职责 |
|---|---|
| `ability-task.ts` | **AbilityTask 接口**。`tick(ctx): boolean`——每个 Task 每 tick 被调用一次，返回 `true` 表示本 tick 完成，ASC 可推进到下一个 Task。`AbilityTaskContext` 携带 `world`、`caster`、`abilityId`。 |
| `task-builder.ts` | **Task 工厂**。`buildTask(cfg: AbilityTaskConfig): AbilityTask`，根据配置类型分发到对应 Task 实现类。 |
| `tasks/wait-ticks-task.ts` | 等待指定 tick 数，期间不做任何操作（用于动画/硬直时间控制）。 |
| `tasks/spawn-hitbox-task.ts` | 在施法者面向方向生成攻击判定框，委托 `HitboxManager.spawnHitbox()` 管理生命周期。瞬时完成（下一 Task 立即推进）。 |
| `tasks/apply-ge-task.ts` | 对 `self` 施加指定 GE（如自身增益）。`hitTarget` 情况由 `SpawnHitboxTaskConfig.hitGeId` 记录，在命中时由 `DamagePipeline` 处理。 |
| `tasks/apply-impulse-task.ts` | 施加物理冲量（`velocity += facing × forwardForce`），实现冲刺位移类技能。 |
| `tasks/play-anim-event-task.ts` | 发送 `ABILITY_ACTIVATE` 和 `GAMEPLAY_CUE` 事件，通知 View 播放对应 Spine 动画和特效。逻辑层**只发事件，不驱动动画**。 |

## battle-core/manager/ — 生命周期管理

| 文件 | 职责 |
|---|---|
| `entity-manager.ts` | **EntityManager**。实体的增删查。`getAll()`、`getAllAlive()`、`getByTeam()`、`getPlayer()`、`generateId(prefix)` 等查询方法。System 通过 `world.entityManager` 访问。 |
| `hitbox-manager.ts` | **HitboxManager**。激活 Hitbox 的生命周期管理。`spawnHitbox(caster, cfg, abilityId)` 创建并计算世界坐标边界；`getActive()` 供 CollisionSystem 每 tick 查询；`tickHitboxes()` 倒计时并清理过期 Hitbox。 |

## battle-core/collision/ — 碰撞工具

| 文件 | 职责 |
|---|---|
| `aabb.ts` | **AABB 工具函数**（无状态）。`aabbOverlap(a, b)` 矩形相交检测；`buildAABB(centerX, baseY, w, h, offsetX, offsetY)` 从实体位置和配置偏移构建矩形。 |
| `hitbox.ts` | **Hitbox / Hurtbox 类型定义**。`ActiveHitbox`（攻击判定框，含 `hitTargets` 防重复命中）；`Hurtbox`（受击判定框，由实体位置 + 配置动态构建）。 |

---

## battle-core/movement/ — 物理运动

| 文件 | 职责 |
|---|---|
| `platformer-physics.ts` | **PlatformerPhysics**。横版平台跳跃物理：`applyGravity()`（非地面时 `velocity.y -= gravity`）；`applyJump()`（地面时 `velocity.y = jumpImpulse`）；`integrate()`（位置积分 + 落地检测 + 水平边界 clamp + 地面摩擦衰减）。 |

---

## battle-core/resolver/ — 伤害公式

| 文件 | 职责 |
|---|---|
| `damage-resolver.ts` | **DamageResolver**（纯函数，无状态）。`compute(req, config, random): DamageResult`。公式：`base = atk × atkMultiplier + flatBonus`；暴击由 `SeededRandom.chance(critRate)` 判定；防御线性减伤 `finalDamage = max(1, floor(base - def))`。不产生任何副作用。 |

---

## battle-core/combat/ — 伤害结算编排

| 文件 | 职责 |
|---|---|
| `damage-pipeline.ts` | **DamagePipeline**。命中后的结算编排（由 `CollisionSystem` 调用）：① 扣 HP；② emit `DAMAGE` + `ATTRIBUTE_CHANGE`；③ emit `GAMEPLAY_CUE`（受击闪白）；④ 受击反应（非霸体时触发击退/击飞/硬直 GE）；⑤ 死亡判定。无敌帧（`State.Invincible`）和霸体（`State.SuperArmor`）在此层处理。 |

---

## battle-core/ai/ — 敌人 AI

| 文件 | 职责 |
|---|---|
| `enemy-ai.ts` | **EnemyAI**（状态机）。`think(enemy, entityManager): AiIntent`，返回 `idle` / `moveToward { targetId }` / `attack { targetId }` 三种意图。距离判断：`attackRange` 内攻击，`detectRange` 内追击，否则 idle。硬直或技能进行中时强制返回 idle。 |

## battle-core/system/ — System 管线（10 个）

> 每个 System 实现 `BattleSystem` 接口（`name` + `update(world, context)`）。
> 由 `BattleDirector` 按**固定顺序**每 tick 调用一次，顺序不可乱。

| 执行顺序 | 文件 | 职责 |
|:---:|---|---|
| 1 | `input-system.ts` | 将 `InputCommand[]` 解析为 `context` 意图字段（`moveX/Y`、`jumpRequested`、`skillSlot` 等）。只写 context，不修改 entity。 |
| 2 | `tag-tick-system.ts` | 维护所有 GE 生命周期（Duration 倒计时、周期触发、过期移除）及所有技能 CD 倒计时。在技能激活之前执行，确保本 tick 状态最新。 |
| 3 | `ability-system.ts` | 处理技能激活请求（优先技能槽 > 普攻）和推进 Task 链。技能执行中不接受新的激活指令。同时推进敌人的 Task 链。 |
| 4 | `movement-system.ts` | 应用玩家移动意图，执行重力/跳跃，对所有实体做物理积分，emit `ENTITY_MOVE`。`Block.Move` Tag 阻止玩家输入移动，但击退物理继续。 |
| 5 | `collision-system.ts` | 遍历活跃 Hitbox × 存活实体 Hurtbox，AABB 相交时调用 `DamageResolver` 计算伤害并交 `DamagePipeline` 结算。末尾调用 `hitboxManager.tickHitboxes()`。 |
| 6 | `hit-reaction-system.ts` | 维护连击数 UI：本 tick 有命中则 comboCount++，否则计时超时归零，emit `COMBO_CHANGED`。 |
| 7 | `combo-system.ts` | 维护普攻连击段数（`comboIndex`）和取消窗口（`comboCancelTicks`）。窗口期内再次按攻击可推进到下一段；超时重置到第一段。 |
| 8 | `attribute-regen-system.ts` | MP 自然回复（每 tick += `mpRegenPerTick`，整数变化时 emit `ATTRIBUTE_CHANGE`）。 |
| 9 | `ai-system.ts` | 调用 `EnemyAI.think()` 获取意图并执行：追击时设置 velocity，攻击时调用 `tryActivateAbility`。 |
| 10 | `battle-result-system.ts` | 每 tick 末尾检测胜负：玩家死亡 → `world.finish('lose')`；所有敌人死亡 → `world.finish('win')`。 |

## battle-core/record/ — 战斗录像

| 文件 | 职责 |
|---|---|
| `battle-record.ts` | **BattleRecord 类型**（`{ version, stageId, seed, startTimestamp, commands[] }`）和 **BattleRecorder** 录制器。`recordCommand(cmd)` 同步录制每条输入；`finish()` 返回完整录像包。录像 + seed 可完全重现战斗。 |

---

## battle-core/replay/ — 离线回放

| 文件 | 职责 |
|---|---|
| `battle-replay.ts` | **BattleReplay**。`replay(record, core)` 将录像中全部 `InputCommand` 预填进队列，调用 `core.runUntilFinished()` 一次跑完，返回全部 `BattleEvent[]`。用于服务器校验和调试回放。 |

---

## battle-core/flow/ — 装配 & 胜负

| 文件 | 职责 |
|---|---|
| `battle-factory.ts` | **BattleFactory**（组合根）。`create(gameConfig, stageConfig, seed): BattleCore`。负责创建并装配所有对象：`BattleWorld`（注入管理器）、生成 `CharacterEntity`（含 ASC 初始化和 GA 授予）、创建 10 个 System 实例、emit 初始 `BATTLE_START` 事件，返回 `BattleCore`。 |
| `battle-outcome.ts` | **BattleOutcome**（胜负裁判）。`check(entityManager, world)` 每 tick 由 `BattleResultSystem` 调用。玩家死亡 → `finish('lose')`，所有敌人死亡 → `finish('win')`。 |

---

## battle-core/application/ — 逻辑层对外门面

| 文件 | 职责 |
|---|---|
| `battle-app.ts` | **BattleApp**。View 层与逻辑层之间的**唯一接口**。构造函数内创建 `BattleCore`、`BattleRunner`、`BattleRecorder`。`sendInput(cmd)` 同时入队和录制；`update(dt)` 驱动 `BattleRunner`；`pause()`/`resume()` 控制暂停；`isFinished()` 和 `getCurrentTick()` 供 View 查询。 |

## battle-view/ — 表现层（Cocos Creator 组件）

> 所有文件都 import `cc`，均不做任何战斗计算。

| 文件 | 职责 |
|---|---|
| `battle-entry.ts` | **BattleEntry**（场景根组件，挂载到战斗场景根节点）。创建 `BattleApp`；每帧采集摇杆输入并节流发 `MoveCommand`；调用 `app.update(dt)` 取回事件后路由给各 View 组件；绑定攻击/技能按钮；维护技能 CD 进度条显示。 |
| `entity-view.ts` | **EntityView**（挂载到每个角色节点）。`init(snapshot)` 初始化血条/蓝条；`onMove(x, y, facing)` 更新节点位置和 Spine 面向；`onHpChange`/`onMpChange` 更新 ProgressBar；`onDeath` 隐藏节点。 |
| `damage-number.ts` | **DamageNumber**（伤害飘字组件）。`show(damage, isCrit, x, y)` 展示飘字并执行上浮 + 淡出 tween 动画。 |
| `virtual-joystick.ts` | **VirtualJoystick**（虚拟摇杆）。触摸事件处理，计算归一化方向并量化为 8 方向（`dx`/`dy` 各为 -1/0/1）。`getDirection()` 供 `BattleEntry` 每帧读取；`isActive()` 判断是否触摸中。 |
| `skill-button.ts` | **SkillButton**（技能按钮）。`updateCooldown(remainTicks, totalTicks)` 更新 CD 蒙版进度条；触摸时若 CD 已就绪则触发 `onPressed` 回调。 |
