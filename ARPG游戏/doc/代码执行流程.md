# ARPG 战斗 · 代码执行流程

> 目的：按**调用链**顺序理解架构如何运行——每个类在什么时候被调用、入参是什么、做了什么、产出什么。  
> 建议先读 [设计文档.md §3.1–§3.3](./设计文档.md)，再对照本文。  
> 路径均相对 `assets/ARPG游戏/scripts/`。

---

## 0. 总览（一句话）

战斗有两种驱动方式，**逻辑内核同一套** `BattleCore.step()`：

```
A. Headless（服务器校验 / 离线回放）
   BattleReplay.replay(record, core)
     → 预先灌入全部 InputCommand
     → core.runUntilFinished()
     → 产出全部 BattleEvent[]

B. 实时交互（Demo 入口）
   BattleEntry.update(dt)
     → 采集输入 → BattleApp.sendInput(cmd)
     → BattleApp.update(dt)
         → BattleRunner.update(dt)  [累积 dt ≥ FIXED_DT 时推进]
             → BattleCore.step()   [每 tick 50ms]
                 → Director 按序调用 10 个 System
                 → world.eventBus.drain() 返回事件
     → View 消费 BattleEvent[]
```

**记忆口诀：**
- 逻辑层（`battle-core/`）**只算不画**
- 表现层（`battle-view/`）**只画不算**
- 输入通过 **`InputCommand`** 进，结果通过 **`BattleEvent`** 出
- 全部随机走 **`SeededRandom`**，全部时间走 **`tick`**（整数，无浮点累积误差）

## 1. 入口阶段：BattleEntry（实时模式）

文件：`battle-view/battle-entry.ts`

```
start()                               // Cocos 生命周期 start
 ├─ app = new BattleApp()             // 创建逻辑层（内部构造 seed）
 └─ 立即 drain() 消费 BATTLE_START 事件 // 工厂在 create() 末尾已 emit

update(dt)                            // 每渲染帧（60fps）调用一次
 ├─ moveTimer += dt
 ├─ if (moveTimer >= FIXED_DT && joystick.isActive()):
 │    moveTimer = 0
 │    dx, dy = joystick.getDirection()   // 8 方向量化
 │    app.sendInput({ type:'Move', tick:currentTick, dx, dy })
 │
 ├─ events = app.update(dt)          // 见 §2
 ├─ for (ev of events): consumeEvents(ev)   // 见 §9
 └─ updateCooldownDisplay()          // 读 asc.getAbilitySpec().remainingCooldownTicks

onPauseBtn()  → app.pause()
onResumeBtn() → app.resume()
```

**关键设计：**
- View **只发 InputCommand**，绝不调用任何 `asc.*` 或 `entity.*` 写方法。
- `moveTimer` 防止每帧发一条 Move，与逻辑 tick 频率对齐。
- `app.update(dt)` 一次可能推进 0 或多个 tick（追帧），View 需能处理批量事件。

## 2. Application 层：BattleApp

文件：`battle-core/application/battle-app.ts`

```
constructor(seed?)
 ├─ seed = seed ?? Math.random() * 0xFFFFFFFF
 ├─ factory = new BattleFactory()
 ├─ core    = factory.create(GAME_CONFIG, STAGE_1, seed)   // 见 §3.1
 ├─ runner  = new BattleRunner(core)                       // 见 §3.3
 └─ recorder= new BattleRecorder(STAGE_1.id, seed)        // 见 §10

sendInput(cmd: InputCommand)
 ├─ core.enqueueInput(cmd)       // 进入 InputCommandQueue（按 tick 分桶存储）
 └─ recorder.recordCommand(cmd)  // 同步录制，供日后回放

update(dt: number): BattleEvent[]
 └─ runner.update(dt)            // 见 §3.3

pause() / resume()
 └─ runner.paused = true / false
```

**职责边界：** `BattleApp` 是 View 与 Core 之间的**唯一门面**；View 只持有 `BattleApp`，不持有 `BattleCore` 或 `BattleWorld`（CD 显示是例外，通过 `app.core.world` 读只读状态）。

## 3. Core 层：装配与 Tick 推进

### 3.1 装配：BattleFactory.create()

文件：`battle-core/flow/battle-factory.ts`

```
create(gameConfig, stageConfig, seed): BattleCore

 ── 步骤 1：创建世界上下文 ─────────────────────────────────
 world = new BattleWorld(gameConfig, stageConfig, seed)
   ├─ random    = new SeededRandom(seed)      // mulberry32 PRNG
   ├─ eventBus  = new BattleEventBus()        // drain 式缓冲区
   └─ tick      = 0

 ── 步骤 2：创建管理器 & 结算器，注入 world ────────────────
 entityManager = new EntityManager()
 hitboxManager = new HitboxManager()
 damageResolver= new DamageResolver()
 damagePipeline= new DamagePipeline()
 physics       = new PlatformerPhysics()
 outcome       = new BattleOutcome()
 enemyAI       = new EnemyAI()

 world.entityManager = entityManager      // System 通过 world 拿到管理器
 world.hitboxManager = hitboxManager
 world.damageResolver= damageResolver

 ── 步骤 3：生成实体 ──────────────────────────────────────
 playerCfg = getCharacterConfig(stageConfig.playerConfigId)
 player = new CharacterEntity(id, playerCfg, 'player', spawnPos)
   └─ 构造函数内部：
        asc = new AbilitySystemComponent(playerCfg.attributes)
        asc.owner = this
        for seg in comboConfig.segments: asc.grantAbility(seg.abilityId)
        for id   in skillAbilityIds:     asc.grantAbility(id)
 entityManager.add(player)

 for spawnEntry in stageConfig.enemies:
   enemy = new CharacterEntity(...)
   entityManager.add(enemy)

 ── 步骤 4：组装 System 管线 ─────────────────────────────
 systems = [
   new InputSystem(),
   new TagTickSystem(),
   new AbilitySystem(),
   new MovementSystem(physics),
   new CollisionSystem(damagePipeline, damageResolver),
   new HitReactionSystem(),
   new ComboSystem(),
   new AttributeRegenSystem(),
   new AiSystem(enemyAI),
   new BattleResultSystem(outcome),
 ]
 director   = new BattleDirector(systems)
 inputQueue = new InputCommandQueue()

 ── 步骤 5：emit BATTLE_START 事件（进入 eventBus，尚未 drain）
 world.eventBus.emit({ type: BATTLE_START, tick:0, entities:[...], room:{...} })

 └─ return new BattleCore(world, director, inputQueue)
```

### 3.2 单 Tick：BattleCore.step()

文件：`battle-core/core/battle-core.ts`

```
step(): BattleEvent[]
 ├─ if (world.result.isFinished) return []
 ├─ commands = inputQueue.dequeueForTick(world.tick)
 │              // 取出 tick ≤ currentTick 的所有指令（追帧追回）
 ├─ director.update(world, commands)   // 见 §4
 ├─ world.tick++
 └─ return world.eventBus.drain()      // 本 tick 全部事件一次性交出
```

`runUntilFinished(maxTicks)` 就是循环调用 `step()` 直到 `result.isFinished`，用于 Headless 模式。

### 3.3 实时累加：BattleRunner.update()

文件：`battle-core/core/battle-runner.ts`

```
update(deltaTime): BattleEvent[]
 ├─ if (paused || isFinished) return []
 ├─ accumulated += deltaTime
 ├─ events = []
 └─ while (accumulated >= FIXED_DT && !isFinished):
       events.push( ...core.step() )
       accumulated -= FIXED_DT           // FIXED_DT = 1/20 = 0.05s
 └─ return events
```

**为何需要 Runner：** 渲染帧率（通常 60fps，dt ≈ 16ms）≠ 逻辑 tick（20/s，50ms）。  
一帧 dt=16ms 不够一个 tick 时，0 次 step；帧率跌到 15fps（dt=67ms）时，1 帧推进 1 次 step。

### 3.4 Director 调度

文件：`battle-core/core/battle-director.ts`

```
update(world, commands)
 ├─ context = new BattleSystemContext(commands)
 │     // 初始值：moveX=0, moveY=0, jumpRequested=false,
 │     //         attackRequested=false, skillSlot=0, hitResults=[]
 └─ for system of systems:
       system.update(world, context)
       if (world.result.isFinished) break   // 战斗结束立即截断
```

System 间通过 **`context`** 传递本 tick 中间意图（Input→Ability），  
通过 **`world`** 持有跨 tick 状态（entity、GE、hitbox）。

## 4. System 管线：一个 Tick 内发生了什么

> 假设 `tick = 100`，玩家在本 tick 按下 Skill1。

### 4.1 InputSystem

```
update(world, context)
 // 重置上帧残留
 context.moveX = 0; context.moveY = 0
 context.jumpRequested = false; context.attackRequested = false; context.skillSlot = 0

 for cmd of context.commands:
   'Move'        → context.moveX = cmd.dx; context.moveY = cmd.dy
   'Jump'        → context.jumpRequested = true
   'NormalAttack'→ context.attackRequested = true
   'Skill1/2/3'  → context.skillSlot = 1 / 2 / 3
```

**输出：** 写入 `context` 的意图字段；不修改任何 entity 状态。

### 4.2 TagTickSystem

```
update(world, context)
 for entity of world.entityManager.getAllAlive():
   entity.asc.tickActiveEffects(world)
     │
     ├─ for age of activeEffects:
     │    if (Duration): age.remainingTicks--
     │      if (<=0): expired.push(age)
     │    if (periodicEffect): age.periodicTimer++
     │      if (>= intervalTicks): timer=0; applyGameplayEffect(periodicGeSpec)
     │
     ├─ for age of expired: removeGameplayEffect(age)
     │    ├─ applyModifiers(sign=-1)    // 反向属性修改（如驱散减速）
     │    ├─ tags.removeTag(...)        // 移除 grantedTags
     │    └─ emit(GE_REMOVED)
     │
     └─ for spec of grantedAbilities.values():
           spec.tickCooldown()          // 所有技能 CD -1（与 GE 同帧处理）
```

**GAS 要点：** GE 倒计时和 CD 倒计时在**技能激活之前**完成，本 tick 减益/CD 状态最新。

### 4.3 AbilitySystem

```
update(world, context)
 player = world.entityManager.getPlayer()

 ── 玩家技能处理 ──────────────────────────────────────────
 if (player.asc.hasActiveAbility()):
   player.asc.advanceActiveAbility(world)   // 推进 Task 链（见 §6.2）
   return                                   // 技能执行中，不接受新激活

 if (context.skillSlot > 0):               // 主动技能优先
   abilityId = playerCfg.skillAbilityIds[skillSlot - 1]
   player.asc.tryActivateAbility(abilityId, world)   // 见 §6.1
   return

 if (context.attackRequested):             // 普攻
   seg = playerCfg.comboConfig.segments[player.comboIndex]
   player.asc.tryActivateAbility(seg.abilityId, world)

 ── 敌人技能推进 ──────────────────────────────────────────
 for enemy of world.entityManager.getAliveByTeam('enemy'):
   if (enemy.asc.hasActiveAbility()):
     enemy.asc.advanceActiveAbility(world)
```

### 4.4 MovementSystem

```
update(world, context)
 for entity of world.entityManager.getAllAlive():
   isPlayer = entity.team === 'player'
   blocked  = entity.asc.tags.hasTag('Block.Move')

   if (isPlayer && !blocked && !entity.asc.hasActiveAbility()):
     if (context.moveX !== 0):
       entity.velocity.x = context.moveX * entity.asc.attributes.getValue('moveSpeed')
       entity.facing = context.moveX > 0 ? 1 : -1
     if (context.jumpRequested && entity.isGrounded):
       physics.applyJump(entity, world)   // velocity.y = gameConfig.jumpImpulse

   // 所有实体（含击退中的敌人）都走物理
   physics.applyGravity(entity, world)   // if (!isGrounded): velocity.y -= gravity
   physics.integrate(entity, world)
     ├─ position += velocity
     ├─ if (position.y <= groundY): 落地归位，isGrounded=true
     ├─ clamp x 到 roomBounds
     └─ if (isGrounded): velocity.x *= 0.6  // 摩擦衰减

   emit(ENTITY_MOVE, { entityId, x, y, facing, isGrounded })
```

### 4.5 CollisionSystem

```
update(world, context)
 hitboxes = world.hitboxManager.getActive()

 for hb of hitboxes:
   attacker = world.entityManager.get(hb.ownerId)
   if (!attacker.isAlive) continue

   for target of world.entityManager.getAllAlive():
     if (target.team === hb.ownerTeam) continue      // 不打同队
     if (!canHitMultipleTimes && hb.hitTargets.has(target.id)) continue

     // 构建目标 Hurtbox（从配置读宽高偏移）
     targetAABB = buildAABB(target.position.x, target.position.y,
                             hurtbox.width, hurtbox.height, 0, hurtbox.offsetY)

     if (aabbOverlap(hb.bounds, targetAABB)):
       hb.hitTargets.add(target.id)

       // ① 计算伤害（纯函数，不产生副作用）
       dmgResult = resolver.compute(
         { attacker, target, atkMultiplier:1.0, flatBonus:0 },
         world.gameConfig, world.random
       )

       // ② 结算伤害（见 §7）
       pipeline.apply({ attacker, target, result:dmgResult,
                        knockbackX, knockbackY, hitGeId }, world)

       // ③ 记录供 HitReactionSystem 使用
       context.hitResults.push({ attackerId, targetId, hitboxId, ... })

 world.hitboxManager.tickHitboxes()   // Hitbox remainingTicks-- 并清理过期
```

### 4.6 HitReactionSystem

```
update(world, context)
 if (context.hitResults.length > 0):
   comboCount += context.hitResults.length
   comboResetTimer = 0
   emit(COMBO_CHANGED, { count: comboCount })
 else:
   comboResetTimer++
   if (comboResetTimer >= 60 && comboCount > 0):
     comboCount = 0
     emit(COMBO_CHANGED, { count: 0 })
```

> 注：实际的硬直/击飞 GE 已在 `DamagePipeline.applyHitReaction()` 内处理，
> 此 System 专注于连击数 UI 维护。

### 4.7 ComboSystem

```
update(world, context)
 if (attackRequested && !player.asc.hasActiveAbility()):
   if (player.comboCancelTicks > 0):              // 在连击窗口内
     player.comboIndex = (comboIndex + 1) % segments.length
   seg = segments[player.comboIndex]
   player.comboCancelTicks = seg.cancelWindowTicks
   player.comboResetTimer  = 0

 if (player.comboCancelTicks > 0): comboCancelTicks--

 if (!player.asc.hasActiveAbility()):
   player.comboResetTimer++
   if (comboResetTimer >= comboConfig.resetTicks):
     player.comboIndex = 0
     player.comboResetTimer = 0
```

### 4.8 AttributeRegenSystem → AiSystem → BattleResultSystem

```
AttributeRegenSystem:
  for entity of getAllAlive():
    regen = cfg.attributes.mpRegenPerTick    // 如 0.25/tick = 5 MP/s
    attributes.modifyCurrent('mp', regen)
    if (整数变化): emit(ATTRIBUTE_CHANGE)

AiSystem:
  for enemy of getAliveByTeam('enemy'):
    if (hasActiveAbility) continue
    intent = enemyAI.think(enemy, entityManager)
      // think() 内：检查 dist → 返回 idle / moveToward / attack
    switch intent:
      'moveToward': enemy.velocity.x = sign(dx) * chaseSpeed
      'attack':     asc.tryActivateAbility(seg.abilityId, world)
      'idle':       velocity.x = 0

BattleResultSystem:
  outcome.check(entityManager, world)
    ├─ if (!player || !player.isAlive): world.finish('lose')
    └─ if (aliveEnemies.length === 0):  world.finish('win')
         └─ world.finish(result) 内：emit(BATTLE_END)
```

## 5. Headless 模式（回放/校验）

文件：`battle-core/replay/battle-replay.ts`

```
BattleReplay.replay(record: BattleRecord, core: BattleCore): BattleEvent[]
 ├─ for cmd of record.commands:
 │     core.enqueueInput(cmd)          // 预填全部输入
 └─ return core.runUntilFinished()     // step() 直到 isFinished

BattleCore.runUntilFinished(maxTicks)
 └─ while (!isFinished && tick < maxTicks):
       allEvents.push(...step())
 └─ return allEvents
```

**校验流程（日后服务器端）：**
```
客户端上报：{ stageId, seed, commands: InputCommand[] }
服务器重现：new BattleFactory().create(gameConfig, stageConfig, seed)
           → replay.replay(record, core)
对比：      result（win/lose）+ 关键属性快照
```

## 6. GAS 详解

### 6.1 tryActivateAbility：技能激活 9 步

文件：`battle-core/gas/ability-system-component.ts`

```
asc.tryActivateAbility(abilityId: string, world: BattleWorld): boolean

 1. spec = grantedAbilities.get(abilityId)
    if (!spec) return false            // 未授予该技能

 2. gaSpec = gasRegistry.getAbilitySpec(abilityId)
    // 从只读注册表读取 GameplayAbilitySpec（costMp、blockedTags、tasks…）

 3. RequiredTags 检查
    if (!tags.hasAll(gaSpec.requiredTags)) return false

 4. BlockedTags 检查
    if (tags.hasAny(gaSpec.blockedTags)) return false
    // 例：技能1 blockedTags = ['State.Airborne', 'State.Stunned', 'Ability.Active']

 5. CD 检查
    if (spec.remainingCooldownTicks > 0) return false

 6. MP 检查
    if (attributes.getValue('mp') < gaSpec.costMp) return false

 7. 扣 MP（仅 costMp > 0 时）
    attributes.modifyCurrent('mp', -costMp)
    emit(ATTRIBUTE_CHANGE, { attribute:'mp', value, maxValue })

 8. 设置 CD
    spec.remainingCooldownTicks = gaSpec.cooldownTicks

 9. 附加激活中 Tag（如 'Ability.Active', 'State.SuperArmor'）
    for tag of gaSpec.activationOwnedTags:
      tags.addTag(tag)
      emit(TAG_CHANGED, { tag, added:true })

10. 构建 Task 链
    tasks = gaSpec.tasks.map(buildTask)
    // buildTask 工厂：WaitTicks→WaitTicksTask, SpawnHitbox→SpawnHitboxTask…

11. 启动 ActiveAbility
    activeAbility = { spec:gaSpec, taskIndex:0, tasks }

return true
```

**数据流向（静态 → 运行时）：**
```
gas-registry（只读 GameplayAbilitySpec）
  ── grantAbility() ──► AbilitySpec（实例，持有 CD 状态）
                              └── tryActivateAbility() ──► ActiveAbility（Task 链执行中）
```

### 6.2 advanceActiveAbility：Task 链推进（每 tick 调用）

```
asc.advanceActiveAbility(world)
 ab = activeAbility
 ctx = { world, caster: owner, abilityId: ab.spec.id }

 done = ab.tasks[ab.taskIndex].tick(ctx)
   │
   ├─ WaitTicksTask:     remaining--; return (remaining <= 0)
   ├─ SpawnHitboxTask:   hitboxManager.spawnHitbox(caster, cfg, abilityId); return true
   ├─ ApplyImpulseTask:  caster.velocity.x += facing * forwardForce; return true
   ├─ ApplyGETask:       asc.applyGameplayEffect(geSpec, world); return true（self 类型）
   └─ PlayAnimEventTask: emit(ABILITY_ACTIVATE, {animName}); emit(GAMEPLAY_CUE,…); return true

 if (done):
   ab.taskIndex++
   if (taskIndex >= tasks.length):   // 所有 Task 完成
     endActiveAbility(world)
       ├─ for tag of activationOwnedTags: tags.removeTag(tag); emit(TAG_CHANGED, added:false)
       └─ emit(ABILITY_END)
       └─ activeAbility = null
```

**例（Skill1 `ga_skill1_dash_slash` 的 Task 序列）：**
```
tick T+0: PlayAnimEventTask  → emit(ABILITY_ACTIVATE), emit(GAMEPLAY_CUE)  → 完成
tick T+0: ApplyImpulseTask   → velocity.x += facing * 8                    → 完成
tick T+0: WaitTicksTask(5)   → remaining=5, 未完成
tick T+1: WaitTicksTask(5)   → remaining=4, 未完成
…
tick T+5: WaitTicksTask(5)   → remaining=0, 完成 → 推进到 SpawnHitbox
tick T+5: SpawnHitboxTask    → hitboxManager.spawnHitbox(…)                → 完成
tick T+5: WaitTicksTask(10)  → remaining=10, 未完成
…
tick T+15: WaitTicksTask(10) → remaining=0, 完成 → 全部 Task 结束
         → endActiveAbility() → 移除 'Ability.Active', 'State.SuperArmor' Tag
```

### 6.3 applyGameplayEffect：GE 施加

```
asc.applyGameplayEffect(geSpec, world)

 if (durationType === 'Instant'):
   applyModifiers(geSpec, world, sign=+1)   // 立即改属性，不入列表
   return

 // Duration / Infinite
 age = new ActiveGameplayEffect(geSpec)
   // age.handle = 唯一 id；age.remainingTicks = durationTicks

 applyModifiers(geSpec, world, sign=+1)
   // 遍历 geSpec.modifiers:
   //   'Add':      current += magnitude * sign
   //   'Multiply': current += base * magnitude * sign
   //   'Override': current = magnitude (sign=+1) / base (sign=-1)
   // 非 hp 属性变化 → emit(ATTRIBUTE_CHANGE)

 for tag of geSpec.grantedTags:
   tags.addTag(tag)
   emit(TAG_CHANGED, { tag, added:true })

 activeEffects.push(age)
 emit(GE_APPLIED, { geId, iconKey, remainingTicks })
```

**GE 移除（过期或主动驱散）：**
```
removeGameplayEffect(age, world)
 activeEffects.splice(idx, 1)
 applyModifiers(age.spec, world, sign=-1)   // 反向修改，还原属性
 for tag of grantedTags: tags.removeTag(tag); emit(TAG_CHANGED, added:false)
 emit(GE_REMOVED)
```

## 7. 伤害：从 Hitbox 到 HP 减少

### 7.1 HitboxManager.spawnHitbox（生成攻击判定框）

文件：`battle-core/manager/hitbox-manager.ts`

```
spawnHitbox(caster, cfg: SpawnHitboxTaskConfig, abilityId)
 worldOffsetX = cfg.offsetX * caster.facing   // 按面向方向翻转
 bounds = buildAABB(caster.position.x, caster.position.y,
                    cfg.width, cfg.height, worldOffsetX, cfg.offsetY)
 active.push({
   id, ownerId:caster.id, ownerTeam:caster.team,
   bounds, remainingTicks:cfg.durationTicks,
   cfg, hitTargets: new Set()         // 防止同帧重复命中
 })
```

每 tick `CollisionSystem` 末尾调用 `tickHitboxes()`，令 `remainingTicks--`，过期则删除。

### 7.2 DamageResolver.compute（纯函数，不产生副作用）

文件：`battle-core/resolver/damage-resolver.ts`

```
compute(req: { attacker, target, atkMultiplier, flatBonus }, config, random): DamageResult

 atk  = attacker.asc.attributes.getValue('atk')
 def  = target.asc.attributes.getValue('def')
 base = atk * atkMultiplier + flatBonus

 isCrit = random.chance(config.baseCritRate)   // SeededRandom，确定性
 if (isCrit): base *= config.critMultiplier    // 默认 1.5

 finalDamage = Math.max(1, Math.floor(base - def))   // 防御线性减免，最低 1 点
 return { finalDamage, isCrit }
```

> **纯函数**：同样输入（含 random 状态）永远产出同样输出，是确定性回放的基础。

### 7.3 DamagePipeline.apply（结算编排）

文件：`battle-core/combat/damage-pipeline.ts`

```
apply(req: { attacker, target, result, knockbackX, knockbackY, hitGeId }, world)

 if (!target.isAlive) return
 if (target.asc.tags.hasTag('State.Invincible')) return   // 无敌帧跳过

 // Step 1: 直接扣 HP（绕过 GE modifier，避免配置 magnitude=-1 被二次放大）
 target.asc.attributes.modifyCurrent('hp', -result.finalDamage)

 // Step 2: emit 伤害事件
 emit(DAMAGE,           { attackerId, targetId, damage, isCrit, hpAfter })
 emit(ATTRIBUTE_CHANGE, { entityId:targetId, attribute:'hp', value, maxValue })

 // Step 3: 受击 GameplayCue（View 播放闪白/音效）
 emit(GAMEPLAY_CUE, { cueTag:'Cue.Hit', position })

 // Step 4: 受击反应（霸体时跳过）
 if (!target.asc.tags.hasTag('State.SuperArmor')):
   applyHitReaction(req, world)
     ├─ if (knockbackX !== 0): target.velocity.x = knockbackX * attacker.facing * 0.1
     ├─ if (knockbackY >= knockUpThreshold):        // 击飞
     │    target.velocity.y = knockbackY * 0.1
     │    target.isGrounded = false
     │    asc.applyGameplayEffect('ge_knockup', world)     // 挂 State.Airborne
     └─ else:
          asc.applyGameplayEffect('ge_hitstun_light', world) // 挂 State.Stunned + Block.*

 // Step 5: 死亡判定
 if (hp <= 0):
   entity.isAlive = false
   emit(ENTITY_DEATH)
```

## 8. GE 生命周期总览

```
施加时                每 tick (TagTickSystem)                 到期/驱散时
──────────────────────────────────────────────────────────────────────────
applyGameplayEffect   tickActiveEffects
  │                     │
  ├─ Instant           ─┤─ （不入列表）
  │    └ applyModifiers │
  │                     │
  ├─ Duration          ─┤─ remainingTicks--
  │    └ 入 activeEffects│    if (0) → expired
  │    └ applyModifiers │
  │    └ addGrantedTags │
  │    └ emit GE_APPLIED│
  │                     │
  └─ Infinite          ─┤─ （不倒计时）
       └ periodicTimer++│    if (>= interval) → trigger periodicGeId
                        │
                        └─ removeGameplayEffect（expired 或主动驱散）
                               ├─ applyModifiers(sign=-1)  // 还原
                               ├─ removeGrantedTags
                               └─ emit GE_REMOVED
```

## 13. 阅读源码建议路线

阅读目的不同，建议路线也不同：

**路线 A：理解整体流程**
1. `data/config-types.ts` — 所有数据结构（先建立词汇表）
2. `battle-core/core/battle-world.ts` — 世界上下文持有什么
3. `battle-core/flow/battle-factory.ts` — 一切从哪里开始
4. `battle-core/core/battle-core.ts` + `battle-runner.ts` — tick 推进机制
5. `battle-core/core/battle-director.ts` — System 管线调度

**路线 B：深入 GAS**
1. `data/gas-registry.ts` — 所有 GA/GE Spec 数据
2. `battle-core/gas/ability-system-component.ts` — ASC 核心 API
3. `battle-core/gas/task/` 各 Task — 技能内部时序
4. `battle-core/system/ability-system.ts` — 每 tick 如何驱动

**路线 C：理解伤害链**
1. `battle-core/collision/aabb.ts` — 碰撞工具
2. `battle-core/manager/hitbox-manager.ts` — Hitbox 生命周期
3. `battle-core/system/collision-system.ts` — 检测入口
4. `battle-core/resolver/damage-resolver.ts` — 纯函数伤害公式
5. `battle-core/combat/damage-pipeline.ts` — 结算编排

**路线 D：理解 View 与 Logic 分离**
1. `battle-core/event/battle-event.ts` — 所有事件类型
2. `battle-core/application/battle-app.ts` — 逻辑侧门面
3. `battle-view/battle-entry.ts` — View 侧入口（只读 event，只发 command）
